# ADR-008: Transactional outbox

## Status

Proposed

## Context

A future owned write may need durable publication.

## Evidence

See current-state verification, bounded-context map, ownership maps, and repository paths cited there.

## Decision

Add outbox/inbox only with an actual event use case and atomic ownership.

## Alternatives considered

Outbox everywhere; dual write.

## Consequences

Reliable publication/deduplication.

## Risks

Schema/operational cost.

## Rollback strategy

Do not activate publisher.

## Approval required

Schema and broker approval.

# ADR-003: First deployable service

## Status

Proposed

## Context

Core domains are transaction/security sensitive; backtesting has a queue and independent scaling need.

## Evidence

See current-state verification, bounded-context map, ownership maps, and repository paths cited there.
The queue inventory and inert skeleton are documented in `backtest-worker-design.md`; lease and heartbeat fields are not yet implemented.

## Decision

Prefer Backtest Worker after queue and scheduler hardening.

## Alternatives considered

Signal, Risk, Identity, Broker, Alerting first.

## Consequences

Operational value with lower core risk.

## Risks

Shared MySQL transition and duplicate claims.

## Rollback strategy

Keep monolith drain enabled.

## Approval required

Approve only after BT-001/2.

Milestone note: the Backtest Worker is now deployable locally with leases and shared-engine parity, but remains disabled and this ADR remains Proposed.
